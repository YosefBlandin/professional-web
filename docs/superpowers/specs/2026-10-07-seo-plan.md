# SEO plan

- **Status:** proposed
- **Date:** 2026-10-07
- **Builds on:** `feat/editorial-redesign` (PR #3)

## Goal

When someone searches for Yosef by name, or for the work he does ("React Native fintech engineer", "Expo NFC tap-to-pay", and similar), the site should:
1. be the first result for **"Yosef Blandin"** on Google and Bing, with the right title, description, photo and links
2. show a clean preview when shared on LinkedIn, X, Slack and WhatsApp
3. be a source that AI answers (Google AI Overviews, ChatGPT search, Perplexity, Claude) can read, understand and cite
4. rank for a few long-tail technical searches that match the CV, through case studies and articles

For a personal site, the first two goals come from technical correctness and entity signals. The last two come from content depth. Keyword tactics don't matter.

## What the research says (October 2026)

- **Fundamentals still decide indexing:** crawlable HTML, one canonical URL per page, unique titles and descriptions, a sitemap and fast pages. AI search surfaces draw from the same index. ([AWR](https://www.advancedwebranking.com/seo/seo-best-practices), [Snoika](https://snoika.com/blog/seo-best-practices-2026))
- **AI answers cite pages they can extract from.** That means clear H2/H3 structure, a direct answer at the start of each section, short paragraphs and entity-focused content. Sites with several interlinked pages on one topic get cited much more often than a single page. ([Revv Growth](https://www.revvgrowth.com/ai-seo/best-practices-for-ai-visibility-seo), [Digital Applied](https://www.digitalapplied.com/blog/seo-after-ai-overviews-complete-strategy-guide-2026))
- **Structured data for a person:**
  - Google documents `ProfilePage`, whose required `mainEntity` is a `Person` with a `name`. Recommended: `image`, `description`, `sameAs`, `alternateName`, `dateCreated` / `dateModified`. A personal "About me" page is an eligible use. ([Google: ProfilePage](https://developers.google.com/search/docs/appearance/structured-data/profile-page))
  - `WebSite` structured data on the home page sets the site name shown in results. ([Google: site names](https://developers.google.com/search/docs/appearance/site-names))
- **Core Web Vitals:** thresholds are unchanged. LCP ≤ 2.5s, INP ≤ 200ms and CLS ≤ 0.1, measured at the 75th percentile of real visitors. ([web.dev summary via PPC Land](https://ppc.land/core-web-vitals/))
- **llms.txt:** none of the major AI crawlers read it, and Google has said it won't support it. **Skip it.** What controls AI access is robots.txt. ([GEOly](https://www.geoly.ai/blog/does-llms-txt-work), [Coronium](https://www.coronium.io/blog/robots-txt-llms-txt-ai-txt-2026))
- **Next.js:** use the file conventions (`opengraph-image`, `icon`, `sitemap`, `robots`) and `metadataBase` instead of hand-written tags. ([Next.js SEO guide](https://stacknotice.com/blog/nextjs-seo-guide-2026))

## Audit of the redesign branch

Checked against the rendered HTML from `next start`:

| # | Finding | Severity |
|---|---|---|
| 1 | **Case-study pages have no `og:image`, `og:type` or `og:site_name`.** Their `openGraph` object replaces the root one. Their `twitter:title` and `twitter:description` still show the **home** text. | High |
| 2 | **Every absolute URL is `http://localhost:3000`** (canonical, `og:url`, sitemap, robots, JSON-LD), because no production domain is set. | High, blocks launch |
| 3 | **The favicon is the Next.js default.** There's no `apple-icon` and no branded icon. | Medium |
| 4 | **The home `h1` doesn't contain the name.** "Yosef Blandin" appears only in the logo and `<title>`, which is weak for name searches. | Medium |
| 5 | **The JSON-LD is a bare `Person`.** It has no `image`, isn't wrapped in `ProfilePage`, and there's no `WebSite` node and no `knowsAbout`. | Medium |
| 6 | **Case studies are thin:** about 250 words of body text each. Their meta descriptions are one short sentence (~90 characters) that names neither the role nor the stack. | Medium |
| 7 | **The sitemap has no `lastModified`.** | Low |
| 8 | **The 404 page is the framework default,** with no way back into the site. | Low |
| 9 | **The `keywords` meta tag is still there.** Search engines ignore it; it's just noise. | Low |
| 10 | **Real-user performance is unmeasured.** Lighthouse lab scores are 100 for Accessibility, Best Practices and SEO, but Performance and field data (CrUX) haven't been checked. Three font families, including Source Serif with an optical-size axis and italics, are the main LCP risk. | Unknown |

## Plan

### Phase 1: technical fixes (on PR #3, before launch)

1. **Production domain.**
   - Set `NEXT_PUBLIC_SITE_URL` on the Worker, for builds and at runtime.
   - Pick one host (apex or `www`) and 301 the other to it in Cloudflare.
   - Use HTTPS only and keep trailing slashes consistent (Next's default has none).
   - Make the code fail the production build if the variable is missing, instead of falling back to localhost.
2. **Per-page social metadata.**
   - In `work/[slug]/page.tsx`, spread the shared Open Graph fields (`type`, `siteName`, `locale`) into each page.
   - Set `twitter.title` and `twitter.description` on each page.
   - Add `work/[slug]/opengraph-image.tsx`, built statically: project title, company and period, the screenshot (or the slip figure for AIDONIC), and the name.
3. **Titles and descriptions:**
   - Home: keep `Yosef Blandin | Mobile & Frontend Engineer`. Description of 140–160 characters naming React Native, fintech and 5+ years.
   - Case studies: `<Project> case study: <what it is> (<main stack>)`, for example `Bangente case study: banking app in React Native and Expo`.
   - Each case study gets its own 140–160-character description covering role, problem, stack and result. Add a `seoDescription` field to `Project`.
4. **Name in the `h1`.** Add "Yosef Blandin" as a small line inside the hero `h1` (for example `<h1><span class="label">Yosef Blandin · Mobile & Frontend Engineer</span> I build…`). Remove the separate eyebrow so the label doesn't appear twice. The visual design stays the same.
5. **Structured data**, as one JSON-LD `@graph` on the home page:
   - **`WebSite`:** `name: "Yosef Blandin"`, `url`.
   - **`ProfilePage`:** `mainEntity` points to the `Person`, plus `dateModified`.
   - **`Person`:**
     - `name`, `jobTitle`, `description`
     - `image` (the portrait at a stable absolute URL)
     - `url`, `email`
     - `sameAs` (LinkedIn, GitHub, Upwork)
     - `knowsAbout` (React Native, React, Next.js, TypeScript, mobile payments, NFC tap-to-pay, data visualization)
     - `knowsLanguage`
     - `worksFor` AIDONIC, if Yosef is comfortable listing it
     - Give it a stable `@id` (`<site>/#person`).
   - **Case-study pages:**
     - a `CreativeWork` with `author`, `about` and `keywords` drawn from the tags, and the screenshot as `image`
     - a `BreadcrumbList` (Home → Work → Project)
   - Validate all of it with the Rich Results Test and the Schema.org validator.
6. **Icons:**
   - `app/icon.svg`: a "YB" monogram in navy and burgundy, readable at 16px.
   - `app/apple-icon.png` at 180px.
   - A minimal `manifest.ts` (name, theme colours, icons).
   - Delete the default `favicon.ico`, or replace it with the monogram.
7. **Sitemap and robots:**
   - `lastModified` on every sitemap entry, from a `updatedAt` field in `src/content`.
   - In robots, allow everything, including AI search crawlers (`OAI-SearchBot`, `PerplexityBot`, `ClaudeBot`, `Google-Extended`) so the site can be cited. Disallow nothing.
   - No llms.txt.
8. **Custom 404:** `app/not-found.tsx` in the site's style, with links to Work and Contact. It must return a real 404 status, not a soft 404.
9. **Clean-up:** remove the `keywords` meta tag. Give the portrait a descriptive file name (`yosef-blandin-portrait.jpg`) so the image URL carries the name.

### Phase 2: performance (measure, then fix)

1. Run a Lighthouse **Performance** trace with the Chrome DevTools MCP on the Cloudflare preview deploy, on mobile with 4× CPU throttling. Targets: LCP ≤ 2.5s, CLS ≤ 0.1, TBT under 200ms.
2. **Fonts.**
   - Check what each family costs. If Source Serif's italic and optical-size axis are heavy, subset to Latin (already the case) and preload only the roman face.
   - Consider dropping JetBrains Mono's 600 weight, which nothing uses.
3. **Portrait (the LCP element).** Confirm `priority` and `sizes` produce a correctly sized AVIF/WebP through the Cloudflare Images binding. Check `fetchpriority="high"` in the HTML.
4. **Real-user data.** Turn on Cloudflare Web Analytics (cookieless). It reports field Core Web Vitals without a consent banner.

### Phase 3: content depth (after launch, for long-tail and AI citations)

1. **Fuller case studies.** Grow each to roughly 500–800 words with fixed H2 sections: *Context*, *Problem*, *What I built*, *Results*, *Stack*. Start each section with a one-sentence answer. Add one diagram or extra screenshot where possible. Link to the previous and next case study, so the six form a cluster.
2. **A Writing section** (`/writing/[slug]`, MDX). Three to five technical articles on topics only Yosef can write first-hand, each linked to its case study:
   - NFC/HCE tap-to-pay in React Native with a custom Expo module (Swift and Kotlin)
   - bridging a Rust cryptography library to React Native through JNI and C FFI
   - right-to-left Arabic and 14-language i18n in a React Native app
   - OCR receipt review behind a feature flag: shipping safely on a backwards-compatible API
   - plotting 10k–20k points: BFS clustering and D3 force layout for a readable heat-map
   - Each article gets `Article` structured data with `author` set to `#person`, its own OG image, and an RSS feed (`/feed.xml`).
3. **Spanish version (optional).** Yosef is a native Spanish speaker in a Latin American time zone. A `/es` version with `hreflang` alternates (`en`, `es`, `x-default`) would reach Spanish-language recruiters and clients. It doubles the copy to maintain, so it's a decision for him.

### Phase 4: off-site signals and monitoring

1. **Search Console and Bing Webmaster Tools:**
   - Verify the domain with a DNS TXT record in Cloudflare.
   - Submit `sitemap.xml`.
   - Request indexing of the home page and the six case studies.
   - Turn on Cloudflare **Crawler Hints** (IndexNow), so Bing and Yandex learn about changes immediately.
2. **Consistent identity across profiles.** These links tie the profiles to the site for Google's knowledge graph:
   - The same name, title ("Mobile & Frontend Engineer · Fintech") and photo on LinkedIn, GitHub, Upwork and the CV.
   - A link to the site from each profile (LinkedIn *Website*, GitHub profile README and `blog` field, the Upwork portfolio).
3. **Links from places that already know Yosef:**
   - his GitHub profile README
   - the SWC contributors list, where applicable
   - client projects that credit developers
   - articles cross-posted to dev.to or Hashnode with a canonical URL pointing back to the site
4. **Ongoing checks:**
   - Monthly: Search Console coverage and queries, Core Web Vitals report, a search for "Yosef Blandin" in Google, Bing, ChatGPT and Perplexity to see what's shown and cited.
   - Re-run the Rich Results Test after content changes.

## Acceptance checks

- Every page has a unique `<title>`, a meta description of 140–160 characters, a self-referencing canonical on the production host, `og:image` (1200×630), `og:type`, `og:site_name`, and matching `twitter:*` tags.
- The Rich Results Test passes for home (`ProfilePage`, `WebSite`) and the case studies (`BreadcrumbList`), with no errors.
- `sitemap.xml` lists every indexable URL with `lastmod`. `robots.txt` points to it. `/nope` returns a 404 with the custom page.
- LinkedIn Post Inspector and the opengraph.xyz preview show the right card for home and for a case study.
- Lighthouse on the production URL scores ≥ 95 for Performance on mobile and 100 for Accessibility, Best Practices and SEO.
- Within 4–6 weeks of launch, Search Console shows the home page and all case studies indexed, and "Yosef Blandin" returns the site first.
